> 점검 화면 크기: 1440×900(데스크톱) / 1024×768(태블릿) / 390×844(휴대폰)

## 1. 🔴 버그 — 실제로 잘못 동작하던 것

### 1-1. `hidden` 속성이 통째로 무력화되어 있었음 ⚠️ 가장 심각

`index.html`은 관리자 전용 버튼을 `hidden` 속성으로 감춰 두었지만,
`css/style.css`의 `.btn { display: inline-flex }` 가 브라우저 기본값 `[hidden]{display:none}`
을 **우선순위로 이겨서** 실제로는 **모든 방문자에게 그대로 노출**되고 있었습니다.

브라우저에서 측정한 실제 값:

```
btnSaveDesign : hidden=true  →  computed display: flex   (화면에 보임)
btnMyDesigns  : hidden=true  →  computed display: flex   (화면에 보임)
btnImage      : hidden=true  →  computed display: grid   (화면에 보임)
```

파생 문제 세 가지:

1. 아무나 헤더에서 **[저장] · [내 디자인]** 버튼을 보고 누를 수 있었음
2. 글자·도형을 선택해도 **[이미지 교체]** 버튼이 떠서, 누르면 텍스트에 사진을 끼워 넣음
3. `body.admin-unlocked` 클래스는 켜지지 않는데 버튼만 보이니,
   그 클래스에 걸어 둔 모바일 대응 규칙(`.brand-name` 숨김)이 동작하지 않아
   **휴대폰에서 헤더 글자와 버튼이 겹쳐 깨짐**

**조치** — `[hidden] { display: none !important; }` 전역 규칙을 추가했습니다.

### 1-2. 편집 도구 막대가 페이지 조작 버튼을 덮음

요소를 선택하면 도구 막대가 미리보기 위에 겹쳐 뜨는데,
그 아래 있던 **페이지 라벨과 [▲▼＋⧉🔒🗑] 버튼이 가려져** 누를 수 없었습니다.

**조치** — 도구 막대가 열릴 때 그 높이만큼 캔버스와 페이지 레일을 함께 아래로 내립니다
(`--tb-space`). 스크롤 중이었다면 같은 값만큼 보정해 화면이 튀지 않고,
맨 위에 있을 때는 보정하지 않아 첫 페이지가 숨지 않습니다.

### 1-3. 편집 도구가 화면 밖으로 잘려 나감

도구 막대는 가로 스크롤만 되고 아무 표시가 없어서, 화면이 좁으면 도구가 사라졌습니다.

| 화면 | 도구 막대 실제 너비 | 보이는 너비 | 결과 |
|---|---|---|---|
| 1024px | 1,051px | 635px | **삭제·복제·잠금·정렬 접근 불가** |
| 390px | 1,171px | 390px | 20개 중 5개만 보임 |

**조치** — 넘치는 도구 그룹을 **[⋯ 더 보기]** 패널로 자동으로 접습니다.
그룹마다 "글자 꾸미기 / 정렬 / 요소 다루기" 이름이 붙어 어디 있는지 바로 알 수 있고,
**글꼴**과 **삭제**는 어떤 화면에서도 항상 도구 막대에 남습니다.
휴대폰(390px)에서도 20개 도구 전부에 닿습니다.

### 1-4. 좁은 휴대폰에서 페이지가 화면 밖으로 삐져나감

`applyZoom()`이 `Math.max(320, 뷰포트너비 - 40)`으로 **최소 320px를 강제**해,
실제로 쓸 수 있는 폭이 274px인 기기에서 320px 기준으로 배율을 계산했습니다.

```
수정 전: 뷰포트 274px 안에 320px 캔버스  →  가로 스크롤 발생
수정 후: 뷰포트 274px 안에 274px 캔버스  →  정확히 맞음
```

**조치** — 하드코딩한 `40`/`320` 대신 실제 패딩 값을 읽어 계산합니다.

### 1-5. 도움말 모달의 ✕ 버튼이 화면 밖 (휴대폰)

`.modal`이 flex 항목의 기본값 `min-width: auto` 때문에 내용(단축키 표) 너비만큼
**440px로 고정**되어, 390px 화면에서 닫기 버튼이 x=415 — **화면 밖**에 놓였습니다.
처음 방문하면 자동으로 뜨는 모달이라 **첫 사용자가 앱에 진입하지 못할 수 있었습니다.**

**조치** — `min-width: 0; max-width: 100%` 추가, 420px 이하에서 단축키 표를 한 줄씩 쌓음.

### 1-6. 편집용 표시가 내려받은 HTML에 섞여 나감

요소·페이지를 잠그면 `data-lh-lock=""` 속성이 붙는데, 직렬화에서 걷어내지 않아
**사용자가 받는 결과물 HTML에 편집기 내부 속성이 그대로 남았습니다.**

**조치** — 잠금 상태는 작업 중 유지해야 하므로 코드창에는 남기고,
**내려받기 · 복사 · 공유로 나가는 결과물에서만** 제거하는 `exportHTML()`을 분리했습니다.

### 1-7. 휴대폰 헤더 레이아웃 깨짐

`.brand-name`에 `white-space: nowrap`만 있고 넘침 처리가 없어 버튼과 글자가 겹쳤습니다.

**조치** — `overflow: hidden` + 말줄임 처리, 560px 이하에서는 브랜드명을 접습니다.

### 1-8. 안내 문구가 다른 UI를 가림

편집 힌트("요소를 누르면 선택…")가 캔버스 아래 가운데에 붙어 있어
**＋ 버튼 및 토스트 알림과 정확히 겹쳤습니다.**

**조치** — 캔버스 위쪽으로 옮기고, 페이지 레일 폭을 피해 배치합니다.

## 2. 🟠 사용성 — 동작은 하지만 쓰기 불편하던 것

### 2-1. 여러 장 문서를 다룰 방법이 없었음 (가장 큰 개선)

6장짜리 카드뉴스를 열면 세로 4,766px 두루마리 하나가 전부였습니다.
지금 몇 페이지를 보고 있는지, 몇 장이 있는지, 3페이지로 어떻게 가는지 알 수 없었습니다.

**조치 — 캔바식 페이지 레일(왼쪽 썸네일 목록) 신설**

- 각 페이지의 **실제 화면 그대로**를 축소해 보여 줍니다
  (html2canvas 같은 무거운 캡처 대신 **축소한 iframe**으로 그려서 즉시 반영되고 정확합니다)
- 썸네일을 누르면 그 페이지로 **바로 이동**, 스크롤하면 현재 페이지가 **자동으로 강조**
- 썸네일 위에서 **▲ ▼(순서) · ⧉(복제) · 🗑(삭제)**
- **드래그로 순서 바꾸기** — [SortableJS](https://github.com/SortableJS/Sortable) (MIT)
- 내용이 바뀐 페이지만 다시 그려 가볍게 동작 (지문 비교 + 0.45초 디바운스)
- `⟨` 버튼으로 접고 펼 수 있고, 선택은 다음 방문에도 기억됩니다

### 2-2. "코드를 몰라도" 앱인데 코드창이 화면 절반을 차지

타깃 사용자는 HTML을 모르는 선생님·학생인데, 첫 화면의 38%가 코드 편집기였습니다.

**조치** — 헤더에 **[⟨⟩ 코드]** 토글을 만들고, **처음 방문하면 접힌 상태**로 시작합니다.
한 번 열면 그 선택을 기억합니다. (모바일은 기존 하단 탭바가 그대로 담당)

부수 조치: 코드창을 접어도 막히지 않도록 **업로드 · 붙여넣기 · 템플릿** 버튼을
문서 단위 동작으로 보고 **미리보기 도구 막대 왼쪽으로 옮겼습니다.**
코드창에는 코드 자체에 대한 동작(복사 · 지우기)만 남겼습니다.

### 2-3. 배율 조절이 드롭다운뿐

캔버스 앱의 관행인 **− / +** 가 없었고, 25% 선택지도 없었습니다.

**조치** — `[−] [자동 맞춤 ▾] [+]` 묶음으로 바꾸고 25% 단계를 추가했습니다.
Ctrl+휠과 동일한 14단계(25%~300%)를 씁니다.

### 2-4. 아이콘 글꼴이 안 열리면 UI 전체가 알아볼 수 없는 영문 덩어리

Material Symbols CDN이 막히거나 느리면 모든 버튼이
`content_paste`, `magic_exchange` 같은 **원문 글자**로 보입니다.
학교·공공기관 망에서 실제로 일어날 수 있는 상황입니다.

**조치** — 글꼴 로딩 실패를 감지해 리거처 원문을 감추고 **버튼 설명(title)** 을 대신 보여 줍니다.

### 2-5. 편집 패널이 페이지 레일을 가림 / 삽입 패널이 잘림

**조치** — 글꼴·색·효과·스타일 패널이 레일 오른쪽에서 열리도록 위치를 잡았고,
삽입 패널 최대 높이를 화면 기준으로 다시 계산했습니다.

### 2-6. 모드 전환 버튼에 접근성 이름이 없었음

**조치** — `title` · `aria-label` 추가.

## 3. 🟡 구조 · 보안 관찰 (설계 판단이 필요한 사항)

### 3-1. 미리보기 iframe의 샌드박스 설정 — 알고 쓰는 트레이드오프

```html
<iframe id="preview" sandbox="allow-same-origin allow-scripts">
```

`allow-same-origin` + `allow-scripts`를 함께 주면 **샌드박스가 사실상 해제**됩니다
(브라우저도 콘솔에 경고를 냅니다). 즉 **남이 준 HTML 파일을 열면**
그 안의 `<script>`가 부모 페이지와 같은 출처로 실행되어
`localStorage`의 저장된 디자인과 **클라우드 비밀번호(`livehtml:gasToken`)를 읽어낼 수 있습니다.**

다만 이 설정은 **이 앱의 핵심 기능(화면에서 직접 편집)을 위해 반드시 필요**합니다.
`allow-same-origin`이 없으면 부모에서 iframe 문서에 접근할 수 없어 편집이 불가능합니다.
이번 작업에서는 동작을 깨뜨리지 않기 위해 **변경하지 않았고**, 선택지만 정리합니다.

| 선택지 | 효과 | 비용 |
|---|---|---|
| 현행 유지 | 기능 그대로 | 신뢰할 수 없는 HTML을 열면 위험 |
| 불러온 HTML의 `<script>`를 기본 차단 + "스크립트 허용" 토글 | 대부분 안전해짐 | 스크립트 쓰는 문서가 처음엔 안 움직임 |
| 클라우드 비밀번호를 `localStorage` 대신 세션 메모리에만 보관 | 유출 피해 축소 | 새로 고칠 때마다 다시 입력 |

> 직접 만든 템플릿과 본인 파일만 쓰신다면 현행 유지로 충분합니다.
> 남이 보낸 HTML을 자주 여신다면 두 번째 선택지를 권합니다.

### 3-2. `js/app.js` 한 파일이 4,300줄

편집 엔진 · 내보내기 · 템플릿 · 관리자 대시보드 · 클라우드 동기화가 한 파일에 있습니다.
지금도 동작에는 문제가 없지만, 앞으로 기능이 늘면
`editor / export / templates / admin / cloud` 정도로 나누는 것이 안전합니다.
(이번 작업 범위 밖이라 손대지 않았습니다.)

### 3-3. 브라우저 대화상자(`confirm` / `prompt`) 사용

페이지 삭제·이름 변경 등에서 OS 기본 대화상자를 씁니다.
앱의 나머지 UI 톤과 다르고 모바일에서 특히 투박합니다.
앱 내부 모달로 통일하면 완성도가 올라갑니다. (이번 작업 범위 밖)

## 4. 검증 방법

실제 Chromium을 띄워 자동으로 조작하며 확인했습니다.

- 템플릿 불러오기 → 페이지 레일 6개 생성 · 썸네일 6개 렌더 확인
- 레일 클릭 → 해당 페이지로 이동 및 활성 표시 전환 확인
- 레일 ▲ 버튼 → iframe 안 DOM 순서가 실제로 바뀌는지 확인
- 레일 ⧉ 버튼 → 페이지 수 6 → 7 확인
- 텍스트 더블클릭 수정 → **코드창에 반영되는지** 확인
- 내보낸 HTML에 `data-lh-*` / `__lh_` 잔여물 없음 확인
- 실행취소/다시실행 · 보기모드 · 매직체인지 · PNG 모달(6페이지 인식) · 도움말 · 색 패널 · 요소 삽입 — 모두 오류 없음
- 1440 / 1024 / 390 세 화면에서 **가로 넘침 0 · 헤더 넘침 0 · 도구 막대 가림 0** 확인
- 콘솔 오류 0건

> 이 점검 환경은 `cdn.jsdelivr.net` 이 차단되어 있어
> **PNG 내보내기(html2canvas) · ZIP 묶기(JSZip) · 드래그 정렬(SortableJS)** 의
> 실제 CDN 로딩은 확인하지 못했습니다.
> 다만 세 가지 모두 **못 받아와도 앱이 죽지 않도록** 되어 있고(오류 0건),
> 드래그 정렬은 **▲▼ 버튼과 Alt+↑/↓** 로 대체되므로 오프라인에서도 순서를 바꿀 수 있습니다.

## 5. 앞으로 하면 좋을 것 (우선순위 순)

1. **iframe 샌드박스 정책 결정** (3-1) — 남의 HTML을 여는 빈도에 따라 선택
2. `confirm`/`prompt` → 앱 내부 모달로 통일
3. `js/app.js` 모듈 분리
4. 코드창에 문법 강조 도입 (CodeMirror 6 등) — 지금은 순수 textarea
5. 페이지 레일에서 **여러 페이지 한꺼번에 선택** (Shift 클릭) 후 일괄 삭제/복제
